# ADR-013: 使用能力门而非交付期限推进

- Status: Accepted
- Date: 2026-07-12

## Context

早期方案使用“首月”和“四周路线”约束初始范围，ADR-007 还包含“一个月内达到可靠生产使用”的时间判断。后续 Human 明确取消月内目标，要求不设 DDL，以架构质量、风险门、验证证据和真实生产可用性决定推进速度。

继续保留时间承诺会产生两个问题：一是诱导实现为了日期跳过 Human Gate 或发布验证；二是让“初始版本范围”和“必须在一个月完成”混为一谈。

## Decision

- `liushi-harness` 不承诺按周或按月完成能力切片。
- 路线图使用 `designed`、`aligned`、`validating` 和 `completed` 等能力状态。
- 每个切片必须通过技术方案、风险、测试、文档、Changeset、发布物和真实项目验证门。
- “初始版本”只表达范围和兼容边界，不表达完成日期。
- Human 可以调整优先级，但不能用时间压力降低历史业务逻辑确认、审批绑定、验证或发布质量。

本 ADR 只废止 ADR-007 中“一个月内达到可靠生产使用”的时间承诺，不改变其多仓读取、单仓写入、Human Gate、Worktree 和 Saga 决策。其他 ADR 中的“首月”统一解释为“初始版本范围”，不再具有日历期限含义。

## Consequences

- 路线进度通过能力与证据报告，而不是周数和日期报告。
- Workflow、Executor、Hooks、Projection、Skills 和 Memory 的顺序必须通过依赖与首个生产用例对齐。
- 未完成的设计不会因为时间经过而自动进入实现或生产状态。
- 发布节奏可能更慢，但不会以隐藏风险换取表面自动化率。
